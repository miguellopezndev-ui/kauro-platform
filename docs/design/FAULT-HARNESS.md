# Common fault harness

One reusable way, for every package from B09 to B19, to test the failure family behind most blocking review findings of B06–B08: concurrency, time (expiry, timeouts), a crash between steps, retries and duplicates, revocation and fencing, partial failure. It lives in `packages/persistence/src/testing/faults/` and is exported from the test-only subpath `@kauro/persistence/testing` (the architecture gate keeps it out of production). Real PostgreSQL 17 only; nothing sleeps to synchronize. Self-test: `packages/persistence/test/fault-harness.test.ts`.

## Primitives

| Need | API | Fails when |
|---|---|---|
| Controlled time | `controlledClock(start?)`: a `Clock` frozen until moved — `advance(ms)`, `set(t)`, `past(boundary, margin?)`, `before(boundary, margin?)`, `at(offset)`; `onServer(session)` sets `kauro.server_now()` of that transaction exactly to the clock (the labelled TEST CLOCK) and checks the server reads it. `moveLog` records each forward move (from, to); `useLog` each read (`now`, `nowMs`, `date`) or transaction positioned by `onServer` (informational: a cell's proof is what its operation's own scope recorded, see Evidence ownership). Moving to the instant the clock already reads is not a move; the instant a move returns is not a use | moved backwards |
| Crash or pause at a named point | `FaultPoints`: `crash(name)`, `pause(name)` → `reached`, `reachedBy(op)`, `release()`, `crash()`; code passes points with `pass(name)`. A crash is recorded when it fires in the code under test, never before | `assertAllReached()`: an armed point never reached; `reachedBy`: the operation finished first; `crash()`/`release()` of a pause already released or crashed throws |
| Crash around COMMIT | `crashableFactory(factory, points, "uow", ["run"])`: points `uow.before-commit` (the unit rolls back) and `uow.after-commit` (committed, answer lost). It records a commit crash only when it fired at its own boundary: before-commit when the factory then rejected (COMMIT never issued), after-commit after the factory resolved (`PgUnitOfWorkFactory` resolves only when COMMIT answered COMMIT). Undecorated members are the real factory's, bound to it (private fields work) | as above |
| Crash around a provider call / dispatch | `instrumentPort(port, points, "storage")`: `storage.<method>.before` (no effect) and `.after` (effect landed, answer lost). An `.after` point (or a factory's `.after-commit`) passed without a crash is recorded as a completed step, by the harness only | as above |
| Process death | `terminateBackend(oracle, victim)`: `pg_terminate_backend` from the oracle (another connection) on the pid the server announced when the victim connected (`connectionPid`, never a query on the victim, which would queue behind a blocked statement); the open transaction is aborted by the server. Recorded in `points.crashes`, but never a crash at a commit boundary | backend survives; oracle is the victim |
| Lock wait | `openConnection(config)` opens a connection the harness owns and hands out only as a proxy (its `query` is the harness's: no query method of the underlying client exists to be bound or cached); inside an operation scope every statement through it is prefixed `/* fault-op:<scope id>:<n> */` and recorded in that scope, dispatched only when the driver sends it (not while queued). `mustWait(oracle, { waiter: connection, holder: pid }, (c) => op(c), what)` → `{ pending }`: runs the operation in its own scope on that connection (idle when it starts, client and server side; while it runs, a statement from outside its scope is refused); the backend's `pg_stat_activity` row must wait on a lock (`wait_event_type = 'Lock'`) in a query that starts with the tag of a statement the operation issued in its scope and the driver is running, and `pg_blocking_pids` must contain the holder's pid; the outcome is re-checked after every look | `InterleavingNotObserved`: a bare pid, a client the harness did not open, or a promise instead of the operation; the connection busy before the operation started; the op settled without waiting, waited only on another backend, or the waiting statement is not the operation's own tagged, dispatched statement (an outside or bypassing statement, the operation's identical SQL still queued) |
| Two-actor race | `inOrder(scenario, first)`, `bothOrders(scenario)`: each actor (`name`, a `client` from `openConnection`, `begin`, `act`) holds the lock once while the other's `act`, run by `mustWait` on its own connection, is observed waiting on it; then holder COMMIT, waiter COMMIT; `verify({ order, state, outcomes })` with each actor's `act`, `commit`, `committed`. A COMMIT answered `ROLLBACK` (an aborted transaction) is a rejected commit (`TransactionNotCommitted`), never `committed`, as in the production factory | the waiter never waited on the holder |
| Duplicates / retries | `concurrently(n, req)`, `sequentially(n, req)`, `partition(outcomes)` | fewer than 2 copies |
| Crash predicate | `crashedAt(point?)` for `assert.rejects` (follows `cause`, as a unit of work wraps the crash) | |

## A matrix cell becomes a test

```ts
faultCell({ id: "B06-R1", step: "LeaseStore.claim takeover", fault: "expiry", expect: "REFUSED RESUME_WITHOUT_CHECKPOINT" }, async (ctx) => {
  const expiresAt = ctx.deadline(ctx.clock.at(120_000), "lease's time to live");  // the boundary the cell names
  // the operation under test takes its instant through the step clock the harness hands it
  const claim = (owner) => ctx.withClock("claim", (clock) => run((uow) => instrumentPort(uow.leases, ctx.points, "leases").claim({ ...input, ownerId: owner }, clock.now())));
  await claim(owner1);                           // the step at t0
  ctx.clock.past(expiresAt);                     // the fault: one move across the deadline
  assert.deepEqual(await claim(owner2), { kind: "REFUSED", reason: "RESUME_WITHOUT_CHECKPOINT" });  // consumed past it, by the claim
});
```

The title is `<id> [<fault>] <step> -> <expect>` (`[<fault> at <at>]` for a crash cell). The body gets a fresh `FaultContext`: `points`, `clock`, `deadline()`, `operation()`, `withClock()`, the counted `mustWait`, `inOrder`, `bothOrders`, `concurrently`, `sequentially`, `attempt()`, and `revoked()`, `fenced()`, `partial()`, `kill()`. `faultMatrix(cells, bodies)` registers a whole matrix keyed by `cellKey` (`id|step|fault`) and refuses a cell without a body, a body without a cell or a duplicated cell, so a package's matrix maps 1:1 to tests.

### Evidence ownership

Evidence belongs to the operation that produced it, never to a position or a time in a shared log. `ctx.operation(name, (op) => ...)` (and every helper that runs an operation: `withClock`, `partial`, `mustWait`, `inOrder`, `bothOrders`, `attempt`, `revoked`, `fenced`) runs the operation under test inside an operation scope with a unique id (`AsyncLocalStorage`, `node:async_hooks`; `faults/scope.ts`). Every evidence source records into the scope current where the evidence happens, and only there (and into the scopes enclosing it): fault points passed, crashed or completed and commit crashes (`instrumentPort`, `crashableFactory`), instrumented calls with their arguments, controlled-clock reads, `onServer` applications (proven consumed by server probes around a statement of the operation), and statements issued through a harness connection (tagged `/* fault-op:<id>:<n> */`, dispatched only when the driver sends them). Evidence recorded outside any scope, in another scope or after its scope closed never counts: the checks for race, expiry/timeout, crash, retry, revocation and partial read only the scopes of the cell's own operations, so a concurrent, unrelated call can never supply a cell's proof. `FaultPoints.passed`/`crashes` and the clock's `useLog` stay as informational logs only.

### Rules: a cell can never pass unless its fault demonstrably happened at the boundary it names

After the body, every armed point must have been reached and the cell's kind must have its proof, recorded only by the harness from what it observed (a flag or a count the body sets is never evidence); otherwise the cell fails with `FaultNotInjected`.

| Kind | Proof |
|---|---|
| `race` | `ctx.inOrder` / `ctx.bothOrders` / `ctx.mustWait` observed the operation itself waiting on a lock held by the intended holder (`pg_blocking_pids`), before it settled: the waiting query carries the unique tag of a statement the operation issued in its own scope through the connection the harness opened and handed it, and that statement is the one the driver is running. A bare waiter pid, a client opened elsewhere, an independent promise, a connection still running an earlier statement, a statement issued from outside the operation (a query method bound earlier included: it is the harness's and refuses), a statement bypassing the handle, or the operation's statement with the same SQL still queued is not this proof. |
| `expiry`, `timeout` | At least one deadline declared with `ctx.deadline(instant)`. Every declared deadline (in any kind) is crossed by one move of the clock (`before < deadline <= after`; `set()` to the current instant is no move, a move short of the deadline proves nothing) and an instant at or past it is then CONSUMED by an operation of the cell (`ctx.operation` / `ctx.withClock`), inside its scope: the instant it read flows into a recorded sink — an `instrumentPort` call (a repository or port, e.g. `instrumentPort(uow.leases, ctx.points, "leases").claim(input, clock.now())`) whose arguments carry it AT the call (p_now style: the instants of the arguments — ISO strings, epoch numbers or bigints, Dates, three levels deep — are copied into a frozen snapshot when the call reaches the port, and only that snapshot is judged), or `onServer` putting it on a transaction in which a statement of the operation then executes. **Server-side proof, no SQL parsing**: `onServer` sets, with `set_config(..., true)` (transaction-local: undone by ROLLBACK, ROLLBACK TO a savepoint taken before it, COMMIT), both the clock override and a unique per-call token `fault.clock_token`, and records the token with the backend pid and `txid_current()`. While the operation runs, each of its statements on that connection (a harness connection, or a plain client tapped by `onServer`) is sent with two harness probes queued in the same synchronous turn, so the driver's FIFO queue holds probe, statement, probe with nothing between them (checked on the queue); each probe reads `current_setting('fault.clock_token', true)`, the clock override and `txid_current()`. **One server statement between the probes**: every statement of an operation on a harness connection (and on a plain client tapped by `onServer`) is sent through PostgreSQL's extended query protocol (`queryMode: "extended"`: Parse/Bind/Execute), so the server itself refuses a multi-statement string ("cannot insert multiple commands into a prepared statement"); a statement the driver did not send that way (a submittable, a client used around the tap) earns no credit. The instant is consumed only if both probes read the call's token, its override and its txid, the statement was sent through the extended protocol (judged only after the driver's `submit()` wrote it without error), the SERVER answered it with a CommandComplete and no error (a statement pg refuses before sending anything — a prepared-statement name used for another text, values that are not an array — never reached the server and proves nothing) and it settled while the operation was open; the cell waits for the probes' answers before it is judged. No statement text is ever parsed to decide this, so whatever was sent — a ROLLBACK TO behind a comment, a DO block or function resetting the clock, a query method cached before the tap — only what the server reports counts. A read whose value reaches no sink (a wrapped, discarded read), an older instant handed to the call, an argument changed after the call, a sink outside the operation, an `onServer` followed only by the transaction's end, a statement after which (or before which) the token or txid differs, a statement sent outside the tap (cached method, other client), a pipelined client, and anything in the body outside an operation are never a use; a step clock refuses every use once its operation settled. |
| `crash-before-commit` | The cell names `at` (the `crashableFactory` name); a crash fired at `<at>.before-commit` inside the unit's work, within an operation of the cell (`ctx.operation`), and the factory then rejected: COMMIT was never issued. A crash at any other point, at `<at>.after-commit`, a point passed by hand or a killed connection is not this proof. |
| `crash-after-commit` | The cell names `at`; the factory resolved (COMMIT answered COMMIT) and a crash then fired at `<at>.after-commit`, within an operation of the cell. Killing an idle connection is not a crash at a commit. |
| `retry` | The request ran and settled at least twice: `ctx.attempt(req)`, or each copy of `ctx.concurrently` / `ctx.sequentially`, counts once its callback executed and resolved or rejected — never on request. |
| `revocation` | `ctx.revoked(what, fn | actorOutcome)` took effect — the function resolved, or a race actor outcome the harness produced inside this cell's `ctx.inOrder` / `ctx.bothOrders` committed — and then `ctx.fenced(what, fn | actorOutcome, refusal)` observed an operation refused after it: the function rejected with the named refusal, or an actor the harness settled after the revocation did not commit and its COMMIT's (or write's) error is the named refusal. |
| `partial` | `ctx.partial(what, at, op)` runs the operation in its own scope with a crash armed at `at` for that scope only (the same point passed by any other call passes unarmed); the operation failed there, and the crash and a COMPLETED step are both in the operation's scope, in that order: an `instrumentPort` `.after` point passed without a crash (the call answered) or a `crashableFactory` `.after-commit` passed without a crash (the unit committed). A `.before` point (an outer call's included), the failing call's own `.after`, a point passed by hand, or a step completed by any call outside the operation — concurrently in the body or in another operation — is no completed step. The body asserts what survived. |

### Threat model

The harness guarantees that a cell cannot pass ACCIDENTALLY without its fault happening at the named boundary of the named operation: evidence from the wrong scope, a concurrent or unrelated call, a statement still queued or untagged, an instant read but never consumed, a transaction undone around the operation's statement, a multi-statement string (refused by the server), or a statement the driver refused before sending it never counts. It does NOT defend against a test body that deliberately subverts its own evidence inside a single server statement — for example a function written to reset the clock override, do its check and restore the override before it returns. That is caught by review; the harness only rejects the obvious forms (a reset that is not restored, a ROLLBACK TO, a multi-statement string).

## Examples

`packages/persistence/test/fault-harness-cells.test.ts` re-expresses four existing tests (the originals stay), each with every assertion of its original: B06-R1 lease takeover without a checkpoint (`expiry`, the lease's time to live declared and crossed, each claim taking its instant through `ctx.withClock` into the instrumented lease store), B08-R1 a revoked source admission fencing a publication (`revocation`: the revocation actor committed, the waiting publication and a later one refused KA081), R2-045 revocation vs publication in both orders (`race`, `bothOrders`; each waiting write runs on its actor's connection, opened by the harness with `openConnection`), B07-R1 a retried release claim vs a newer hold (`retry`, three attempts of the release request; the 900-second claim and its 10-second in-flight bound, the database's refusals of a second live claim, a release under an unanswered claim, a superseded answer, a premature hold and a claim for an undecided release, the once-only answer and the persisted claims and holds; the clock crosses the claim's bound and the in-flight bound, both declared, and each transaction on the clock is positioned by its own step clock and then runs the operation's statements). Self-test of every rule, including each vacuous cell that must fail: `packages/persistence/test/fault-harness.test.ts`.
