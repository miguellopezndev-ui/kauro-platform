# KC codes: the register of database refusals (package B10)

One row per `KC` SQLSTATE the migrations raise or will raise. The check `tools/test/kc-codes.test.mjs` (cell 28, ledger
`[g6c-r2-kc-codes]`) reads this file, `packages/persistence/migrations/*.sql` and `packages/persistence/src/sqlstate.ts`.

Columns: code | message prefix (`TOKEN:`, judged on the LAST `CREATE OR REPLACE` of each raising function in migration order) |
MAP code | MAP reason (`-` when the MAP entry carries none) | SQLSTATE name (key in `sqlstate.ts` `SQLSTATE`) | lane | status.

Status meaning: RAISED = must be raised; PLANNED = may be raised, meaning fixed; RESERVED = must not be raised yet.
