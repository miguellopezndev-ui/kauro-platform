# Failure-mode matrix: template

Owner rule: before code, every stateful command, transition, consumer or sweep has a matrix. Codex's blocking findings in B06 to B08 were one family found one per round (race with another actor, timeout, expiry during a step, crash around the commit, retry or duplicate, revocation mid-way, partial failure). The matrix finds them before the review does.

## Shape

One table per command, transition, consumer or sweep. **Rows** are the steps that write or call out (one COMMIT, one port call, one lease claim). **Columns**, in this order:

| Column | Definition |
|---|---|
| RACE | Another actor (command, consumer, sweep, second instance) touches the same row or lock between this step's read and its COMMIT; both orders. |
| TIMEOUT | A lock wait, statement or port call exceeds its limit; the caller cannot tell whether the effect happened. |
| EXPIRY | A deadline (price, claim window, step-up, lease, retention) passes during the step; the database clock decides. |
| CRASH-BEFORE | The process dies after the step's last write and before COMMIT; nothing may remain. |
| CRASH-AFTER | The process dies after COMMIT and before the answer or the outbox settle; the retry must return the committed result. |
| RETRY | The same key (replay) or the same event (duplicate delivery) arrives again, or the same key with a different body (conflict). |
| REVOCATION | The acting authority (grant, membership, step-up, verified destination, lease fence) is withdrawn mid-way. |
| PARTIAL | One write of a multi-write step succeeds and a later one fails; no half-state may commit. |

## Cells

Each cell is exactly one of: **C** expected behaviour plus the proving test as `file :: "exact title"`; **GAP** the behaviour the design implies, plus a gap code (the test is then written first); **N/A** with the reason it cannot occur (a read-only step, a single statement). An empty cell is not allowed. A retry test does not prove CRASH-AFTER: the replay is proven, the injected loss is not.

## Naming tests

`RACE ...` for an interleaving or crash (the title lists the cases: retry, conflicting key, crash at the commit boundary); `DENY ...` for a refusal (foreign scope, wrong role, then one missing prerequisite at a time); `OK ...` for the success path; a suffix in parentheses names the family, e.g. `RACE (timeout): ...`, `RACE (crash after COMMIT): ...`, `RACE (replacement): ...`. A title names its example or rule id when it has one ("R2-137 (examples 9 and 10)"). One title, one file, unique inside the file; the case map and the matrix cite `file :: "exact title"`.

## Rule: a family seen twice becomes a matrix rule

When two Codex findings (in any package) belong to the same column family, the family stops being a finding and becomes a rule here: its column gets a default expected behaviour and a default test title in this template, and every new matrix must fill the cell from it. Rules so far are the eight columns above and the family rules below; add new ones with the package and finding ids that justified them.

## Family rules learned

Codex's design-time review of the B10 matrix (r1, 17 findings) found the same few mistakes repeatedly. Each recurring family is now a rule that every matrix must satisfy before it is sent to review.

1. **Sequential calls never prove a race.** A RACE cell is C only if the test holds one actor at a named lock or await point and runs the other, in both orders (or concurrent recovery of the same key). A test that finishes the first call before it starts the second is a DENY or OK guard; the cell is a GAP (B10-M7).
2. **A crash cell names the exact COMMIT it straddles.** CRASH-BEFORE is C only when the injection point is after the step's last write and before its own COMMIT; an injection before the step starts, or before another transaction's COMMIT, proves another cell. CRASH-AFTER names the COMMIT after which the response or the settle is lost (B10-M8, M9).
3. **Every external effect with more than one durable write is split into one row per write.** A payment-service re-binding, a funds effect, a conversion, a compensation, a delivery claim: one row per transaction and per write that can fail alone, each with its own PARTIAL and CRASH cells (B10-M1, M2, M6, M11, M12).
4. **A guard, a CHECK or a database invariant is not a partial-failure test.** PARTIAL is C only when a failure is injected at a second or later write and the test asserts the complete footprint, including the journal, rolled back. A single-statement step is N/A with the invariant cited as a DENY (B10-M10).
5. **A retry or success test proves neither CRASH-AFTER nor RETRY of an event.** Redelivery of the identical event needs its own test; an observed success path is an OK test (B10-M11).
6. **Every call-out and read in the inventory is a row.** A port call (inspector, verifier, reader), a trigger, a state transition performed by another command, and the ordinary write path of a command all get a row, even when another row already covers the same transaction (B10-M3, M4, M5).
7. **The expected behaviour is read from the design section that governs it, with the decision id.** Pre-settlement and post-settlement behaviour are different cells; an expiry cell names the deadline that governs (for a claim, its tail end when listed); the race cell names every actor on the calculation, not only a copy of the same command (B10-M9, M13, M14, M16).
8. **Authority revocation covers every prerequisite of the step, not only the grant.** A mandatory fact the step reads (identity, MFA, destination, agreement) is revocable mid-way and needs its own REVOCATION cell (B10-M17).
9. **Money and authority GAPs are tier 1, whatever the column.** A crash, partial or retry GAP of an effect that decides payable rights, forfeits a right or admits an expired actor is tier 1; tier 3 is a retriable error with no wrong outcome (B10-M15).
10. **Name the state a compensation leaves, not the state it started from; and assert the amount, not the object.** A refusal or rollback preserves what another actor already committed (an entitlement CONSUMED or REVOKED stays so), and a partial hold withholds its cents while the rest of the line is paid (B10-M9, M14 r2).
11. **A capacity/limit invariant is enforced by every writer of either side under one lock, with a RACE cell per writer pair.** List every writer that changes either side of the bound (the consumers and the capacity: an offset and a hold, a reservation and a slot), take the same lock in all of them before the capacity read, and give each pair of writers its RACE cell in both orders; a writer that cannot be refused (a refund lowering the capacity) is a listed caveat with its decision, never silent (B10 kit PR1 ADV-3, ADV-9, ADV-10).
11a. **Row locks are `FOR NO KEY UPDATE` unless the key changes.** A writer that locks a row it will not re-key (a state transition, a version bump) takes `SELECT ... FOR NO KEY UPDATE`, never `FOR UPDATE`: every insert that references the row takes its KEY SHARE through the foreign key, `FOR UPDATE` blocks it, and with a transition lock (shared/exclusive halves) that closes a 40P01 cycle for one reader order or the other. The matrix lists, for each subject a writer row-locks, the readers that insert rows referencing it and the order in which they take the shared half and the KEY SHARE, with a lock-order cell per reader order in both interleavings (B10 kit: CMD043 and CMD002 against CMD028's continuation and the journal reservation; adversary ADV-1 of 593c47f). The exception is a `FOR UPDATE` that is the serialization point against inserts which take no lock of their own beyond the foreign key's KEY SHARE (the commission line locked by CMD051 against a hold inserted on it: CLOSE_HOLD_RACE fails under NO KEY because the close no longer waits for the uncommitted hold). Such a lock stays `FOR UPDATE` only when the matrix names those inserts, shows they take no transition half before their insert (so no cycle exists), and has the RACE cell that fails under NO KEY; otherwise the inserts take a transition half and the row lock becomes NO KEY.
12. **One forged control per atomic predicate.** An invariant, guard or oracle branch that joins predicates (OR, a count compared with exactly one, IS DISTINCT FROM over an absent row) is split so each predicate has its own name and a negative control that fires it alone; a control that fires through a neighbouring predicate proves nothing about its own. COALESCE/absent cases are separate predicates: no COALESCE, IFNULL, NULLIF or CASE WHEN ... IS NULL reads an absent row or column as a value; the absent case is its own branch (NOT EXISTS, IS NULL) with its own name and its own control that forges the ABSENT state (B10 kit PR1 ADV-2, ADV-11, ADV-16).

13. **Every new lock names its place in the lock order and the locks already held there.** A new row, advisory or table lock names its position in the documented lock order and the locks the actor already holds at that point; a lock taken while another is held needs a RACE cell forcing the opposite order (both actors), red without the ordering guard. A lock that cannot be placed in the order is only tried (never waited for) after the other is held, and its refusal is a declared retryable outcome (P0 of main 8f4f2f3, ADV-5 of 3154481: the first-issuance lock waited for behind a quote row lock deadlocked two CreateQuotes).

14. **A test repair keeps the behaviour it touches, and a count must be able to fail.** A test repair that removes or replaces a case must keep a case for the same behaviour, and every footprint/count assertion must have a fixture where the expected value is non-zero. An expected value read back from the result it checks (`events: fp.events`) is not an assertion (PV1 L-ROUTE adversary r1, ADV-PV1R-4/-5/-8: the incomplete-details case dropped by a repair, participant removals by raw DELETE, self-equal event counts).

15. **TIME-AFTER-AWAIT: a time judgment uses an instant read after the last await before it; no await between the final judgment and the effect; each such judgment has a cell that delays the last awaited step across the boundary.** Session idle/absolute expiry, step-up freshness, instruction deadlines, details validity and transfer windows are judged at a clock read after the judgment's last I/O (a store statement, a proof read, a pool acquisition, a re-authentication), or in SQL in the statement that reads the row; a verifier that reads then judges at a caller-supplied instant returns a bound the caller judges later (FRESH.freshUntil). The cell holds that LAST awaited step (not an earlier one) and crosses the boundary during the hold (PV1 L-ROUTE Codex r2, PV1R-02/03/06: three findings of one family, each a sample taken before the await it was judged after).

16. **An authority judgment that gates an effect is taken under a lock that conflicts with the writer that revokes/renews that authority, with the clock read after the lock is granted and the effect completed before the lock is released; reordering awaits is not a fix.** The judge locks the authority's row (FOR UPDATE, or FOR SHARE where it never writes it) in a statement of its own, reads the clock in a later statement (never in the locking SELECT's target list: it is evaluated before the lock wait), judges revocation and every deadline from the locked row at that instant, completes the effect (view built, unit committed) and only then releases; the revoking and renewing writers take a conflicting lock (UPDATE). A renewal (touch) decides at an instant read after its own lock wait and never renews an ended authority. Cells: the writer races the judgment at the lock in both directions (committed before the lock is seen; started after the lock waits until the effect is complete) and the deadline is crossed while the judge waits on the lock (PV1 L-ROUTE Codex r3, PV1R-02/07: the second round of the TIME-AFTER-AWAIT/REVOCATION family, where every reorder of the session read and the clock read left a gap). **The lock is held by the transaction that commits the effect or builds the view: same connection, same transaction, same lifetime (PV1 L-ROUTE Codex r4, PV1R-07).** A lock held by another transaction (another pool, another connection, a hold kept open beside the effect) is not a fence: its backend can die while the effect's transaction lives on, the database releases the lock, the revocation commits and the effect commits on a judgment of a row no longer held; no liveness check of the other holder closes this (the check and the COMMIT are two instants). The authority's state is read by the locking statement in that same transaction, never from a record cached by another one. The release is that transaction's COMMIT: a failed COMMIT or release of any authority-bearing transaction fails the request before any byte of the answer is sent and is never only logged. When the effect's role holds no privilege on the authority's row, grant the narrowest lock-only path (column SELECT of the judged columns, UPDATE on one immutable column, an UPDATE policy WITH CHECK (false)) before any SECURITY DEFINER. Cells: the backend holding the lock is terminated between the lock and the judgment and between the judgment and the COMMIT, the authority is then revoked and committed, and the effect is released: nothing commits, no successful view, the next request is refused; one assertion names the effect's own backend as the only holder (pg_blocking_pids).

17. **Every writer of a guarded aggregate takes the aggregate's lock before reading it, direct INSERT grants included, and each writer pair has a RACE cell.** A guarded aggregate is any sum or state a guard compares against (a capacity, a live amount, a recognized balance, an itemized total, a settlement, a proposal hash). The guard itself (a trigger on every INSERT/UPDATE path, not only the application path) takes the subject lock of the aggregate, after the writer's row locks in the global order, and reads only after it; a deferred COMMIT check is a backstop, never the serializer (READ COMMITTED sees its own rows only). A writer that touches several aggregates computes its whole lock set first (discovery read), locks rows then subjects ascending, re-reads and refuses if the set grew. The design lists, per aggregate: its lock, every writer including direct grants, and the RACE cell of each writer pair in both orders (rules 1 and 11), plus the TIMEOUT cell of a guard that waits. Rules 13-15 are on `sec/depth-provenance`; the merge keeps the numbers (B10-OFFSET Codex design r1 OFF-R2, OFF-R3, OFF-R4; r2 OFF-R2-01, OFF-R2-02, OFF-R2-04; adversary ADV-10, ADV-17).

18. **A derived value is bound whole, at birth and at every update, and no immediate decision reads a value checked only at commit.** Every column of a derived row (counts, sequences, instants, scope, attribution, bookkeeping such as ledger sequences and allocations) is bound to its facts or normalised by the database on INSERT as well as on UPDATE: a column DEFAULT, an INSERT column grant or an RLS policy is not a binding. Every deferred relation check is queued per parent row on INSERT and on UPDATE of its derived columns, and per child row, so an empty relation (a parent with no children) is checked too. A decision taken before COMMIT (a last-owner refusal, a still-owed amount) reads the facts under the lock that orders it, never a cache whose correctness is only re-checked at COMMIT. The matrix carries an "inflate, decide, restore" DENY for each cache and a forged-birth DENY for each derived column (SEC-DEPTH SDP-20, SDP-28, SDP-30).

19. **A source-to-derived relation is checked both ways, at birth and update, and the evidence is frozen once used.** Each source birth and transition has its derived record (structurally, by an AFTER trigger of the source, or by a deferred check), each derived record has its source and is consumed, the complete final relation is re-selected at COMMIT, and the source facts an accounting record cites can no longer change or be deleted. The matrix carries source-only, orphan-record and post-consumption-mutation DENY cells (SEC-DEPTH SDP-21, SDP-26).

20. **Every new DENY predicate has a named OK sibling for each unchanged production writer, at birth and update.** Each writer attachment, birth path, resource kind, scope, timing (BEFORE/AFTER row visibility, multi-row, separate statement) and first-use state (no checkpoint yet, no prior row) commits through the production writer; a guard that reads a source row states the trigger phase in which that row is visible (SEC-DEPTH SDP-22, SDP-24, SDP-25).

21. **Every added lock has its place in one global lock order and a stated mode.** The design names the order across all actors that take the same rows (sweeps and retained writers included), the lock mode (never a weaker lock later upgraded, e.g. an FK KEY SHARE followed by FOR UPDATE), and what a writer that cannot follow the order does (fail fast with NOWAIT, never wait while holding a later lock). The matrix carries a RACE cell, both orders held at the lock, for every pair of actors on those rows (SEC-DEPTH SEC-109, SDP-29).

22. **Lifetime binding is enumerated per table, not per finding.** Before a design that guards derived values, facts or evidence goes to review, it carries one matrix row per table any of its guards reads or protects, with these cells: INSERT (birth binding; a seeded row or singleton has a birth path too), UPDATE for each guarded column (the exact permitted transition, e.g. "+1 by operation X while fact Y", never "no decrease" or a range cap alone), DELETE, TRUNCATE (fires no row trigger), identity/reparent (key and parent columns), and the deferred checks with what queues them per parent and per child. Every cell names its guard or states "not needed because <fact>". The DENY cells and their OK siblings are generated from that matrix; tables read only by guards outside the design are listed as a named residual. The table and column list is never assembled by hand: a read-only extractor over the guard function bodies (e.g. `tools/sec/guard-reads.mjs`) emits it, and a test fails when any extracted column has no cell or residual entry; every learned-once (NULL -> value) column needs its own cell naming the only operation that may first assign it and the value it gets Text is not a binding: every cell names its enforcing trigger, and the extractor verifies that trigger fires on that column's write (no UPDATE OF list or one naming the column; no WHEN, or one reading the column; on INSERT too for a first assignment) and reads the column; a state-edge trigger never binds a column that can change without the edge. Every append-only or snapshot table whose values feed money or authority has a birth binding to its authoritative source rows in the same transaction, checked both ways. A residual may hold only tables that feed neither money nor authority (SEC-DEPTH SDP-30, SDP-31, SDP-32, SDP-34, SDP-35, SDP-36, SDP-37, SDP-38). Never certify by mention: a trigger WHEN covers a column only when absent, an exact disjunction of `OLD.c IS DISTINCT FROM NEW.c` terms naming it, or a reviewed text on an allowlist; a read counts only for that column of that row (SDP-41).

23. **Eligibility windows run on the database clock, and every "first X" has an absence proof.** An instant that bounds a money or authority window (issuance, as-of, lookback, expiry, deadline) is the database clock at birth, never a caller value; a copy of an earlier window is allowed only on a named historical-copy path checked against its source row. An eligibility that depends on something not having happened yet (first purchase, founding offer, first designation) is checked by a NOT EXISTS over the facts, under the lock that orders the competing writer, held to COMMIT (SEC-DEPTH SDP-39, SDP-40).

24. **A RACE cell names the first lock its two actors meet, and goes red when that lock alone is removed.** For each writer pair the plan has a meeting table: the locks each actor takes in order, and the first one they share (the meeting point). A race cell names that meeting point. If a lock taken earlier by both (for example a per-person or per-aggregate lock added for a cap) is shared, the cell either names that earlier lock or picks an actor pair that does not share it. Each race cell has a lock-removal control: with the named lock removed or downgraded and everything else unchanged, the cell is red; a cell that stays green is not C. Adding a lock before existing ones re-derives every race cell whose actors now meet there first. An expected outcome that differs by order is stated per order. (B12 plan adversary ADV-4 r1, ADV-23 r2.)

25. **Every time judgment has an await-table row, and its expiry cell pauses at that row's last await.** The plan lists for each judgment the last await before the clock read, the clock read itself (database clock, after every lock wait) and the effect; there is no await between judgment and effect. The expiry cell holds exactly that last await across the boundary, never an earlier one, and a planted await between judgment and effect turns a static check red. (B15/B17/B18 plan adversary ADV-4 r1, ADV-24 r2; rule 15 applied twice without the table.)

## Kit lints

K1. **SQL-shape lints are allowlists of exact permitted forms, never denylists.** A lint over oracle or guard SQL (the nonAtomic() check of B10-KIT-SUITES 2.1) names the exact forms it permits (a scalar subquery only as a row source or one exact count; a CASE ELSE only in its pinned shapes; the shared CTEs as their pinned text) and refuses everything else; a denylist grows one finding per bypass (B10 kit PR1 ADV-19, ADV-21, ADV-22). A quoted identifier is refused in a branch except COLLATE "C".

## Mapping to the fault harness (`docs/design/FAULT-HARNESS.md`)

| Column | Harness facility |
|---|---|
| RACE | two-actor interleaving, both orders, held at a named lock or await point |
| TIMEOUT | injected delay or failure at a port or statement, with the controlled clock past the limit |
| EXPIRY | controlled clock set to the instant before, at and after the deadline |
| CRASH-BEFORE / CRASH-AFTER | crash injection at the commit point (before and after) and at each await point between writes |
| RETRY | replay of the same key and event, and the same key with another body |
| REVOCATION | an interleaved revocation committed at the held point, before and after the guard |
| PARTIAL | crash or failure injected at the second and later write of a step |

A GAP cell is closed by a test that uses the matching facility, named in the cell's proposed title (`RACE ...`, `DENY ...`), and the cell is then rewritten from GAP to C in the same commit.
