# B07 — case map

Every case of package B07 (registry `program.json` B07 `caseIds`, `node tools/package-brief.mjs B07`: 23 cases, gate G-UPLOAD,
owner 09) mapped to the tests that demonstrate its expected outcome, to what a sealed check observes, and to the later package
that owns any clause B07 cannot demonstrate. Design: `docs/design/B07-upload-source-lifecycle.md` (decisions `D-*`, commands §11,
pipelines §12, critique record §18). The state/command/event matrix, including the four B07 machines and the B07
commands and routes with their outcome catalogues and contract-test applicability, is generated in
`docs/design/B06-state-command-event-matrix.md` (`tools/matrix.mjs`, checked by `pnpm run verify`); every B07 route is documented
in `apps/api/openapi.json` from its contracts (`tools/openapi.mjs`, D-API-1) — an `x-kauro-planned` operation until mandate
B07-COMMANDS served it under `paths` (D-CMD-11, D-CMD-16).

Every test is cited as `` `file` :: "exact test title" ``. `tools/test/b07-case-map.test.mjs` (part of `pnpm run verify`) reads this
file: a cited file that exists must contain a test with exactly that title, and a cited file that does not exist yet must be one
of the files the implementation mandates create (§15 of the design) — so no EXECUTED_LOCAL row can name a test that does not run.

Status vocabulary (21 "Evidence classes"; every claim names its class):

- **EXECUTED_LOCAL** — the named test exists under exactly that title and passed in `pnpm run verify` of `b07/integration` (the
  design head `ef284df` with the three stage-1 and the two stage-2 mandates merged) on Windows and on Linux. Database tests start a real PostgreSQL 17 cluster,
  drive every write through the runtime login role that owns it (`kauro_app_test` as a request handler, `kauro_control_test` as the
  control plane bound to one agency) and use the superuser as the oracle only; they prove what the database refuses and admits
  whatever the application does. Domain and application tests run the pure model and the contracts. The rows citing
  `packages/persistence/test/source-adapters.test.ts` were added by mandate B07-PERSISTENCE (branch `b07/persistence`): the same
  real clusters and runtime roles, driven through the `pg` adapters of the source-store ports and `runSource` (every repository
  method, typed refusals, lock waits observed in `pg_stat_activity`). The rows citing `packages/data-plane/test/*` were added by
  mandate B07-DATA-PLANE (branch `b07/data-plane`): the platform's own parsers, always real, run in their isolated child process
  (D-ISO-1) — they are EXECUTED_LOCAL, not SIMULATED, because the inspector and the evaluator are not providers (design §2). The
  rows citing `apps/api/test/cmd012…cmd017-*.test.ts` and `source-reads.test.ts` were added by mandate B07-COMMANDS (branch
  `b07/commands`, from `b07/stage-1`): every request through the real HTTP route and composition root over the same real clusters,
  the control plane's steps between the commands written by the product's adapters in control-plane units of work bound to the
  agency (`apps/api/test/source-support.ts`, design D-CMD-15). Such a row is EXECUTED_LOCAL when the clause it names is decided by
  the handlers and the database; it is SIMULATED when the clause rests on the labelled storage or vault fake (a delivered session, a
  completion reference parsed by the storage port, a generation changed at the provider). The rows citing `apps/control/test/*`
  were added by mandate B07-CONTROL (branch `b07/control`): the control plane's own dispatcher, consumers and sweepers over the same
  real clusters. The rows citing `apps/control/test/end-to-end.test.ts` were added by the `b07/integration` integrator (design §16.5,
  D-INT-1): the application's own handlers of CMD012..CMD017, the source reads and the manifest intake on B06's pipeline, each answer
  checked against its route's response contract, composed with the control plane over one cluster and one set of labelled fakes.
  Every control-plane and end-to-end row is SIMULATED: its clause passes through the labelled storage, scanner, vault or journal fake.
- **SPECIFIED (mandate)** — the command-, pipeline- or parser-level half: the design fixes the exact behaviour (§11, §12) and the
  row names the test the implementation mandate writes (planned file :: planned title). A SPECIFIED row is not claimed.
- **SIMULATED** — a clause demonstrated only through a labelled contract fake of a provider port (object storage, malware scanner,
  session vault, authority journal; provider tokens `contract-fake-*`, evidence class SIMULATED); the test passed in the same
  `pnpm run verify`. Until B15 binds the real adapters these clauses are never EXECUTED_PROVIDER.
- **LATER** — a clause another package owns, named with the package and its registry case where the registry has one.

No case is PASS by being listed; acceptance is the construction service's independent review. The planned tests follow B06's
placement (command cases through the real HTTP route and composition root in `apps/api/test/`; database facts in
`packages/persistence/test/`; parser facts in `packages/data-plane/test/`; control-plane pipelines in `apps/control/test/`), every
fixture writes as the role that owns the write (`@kauro/persistence/testing` source-lifecycle fixture) at the server's instants
(the labelled TEST CLOCK stands a fixture in the past, D-CLOCK-1), interleavings are fixed by lock-wait observation, never by time,
and the oracle is the superuser reading every table.
