# B16 team commands CMD003-CMD007: design and failure matrix

Scope: InviteMember (CMD003), AcceptInvitation (CMD004), ChangeMembership (CMD005), RevokeMembership (CMD006), TransferOwnership (CMD007). The other B16 operations (CMD056/057 recovery, migration 0057) were built by b18/gaps and are not repeated here. Tests are `apps/api/test/cmd00{3,4,5,6,7}-*.test.ts`; shared fixtures are `apps/api/test/team-support.ts`.

## Decisions

- **D-TEAM-1 (token delivery).** The raw invitation token is never a response member (the response guard FORBIDDEN_RESPONSE_FIELDS names `invitationToken`, 08). The command result carries it as `oneTime`; after the COMMIT the server hands it once to the configured delivery channel (`ApiAssembly.oneTimeDelivery`; the production e-mail adapter is a provider adapter of another package, GAP; absent, it is dropped). It is never journaled, never in an event payload and never replayed; only its SHA-256 is stored (08 "one-use, time-limited opaque tokens, stored hashed"). A lost response, a crash before delivery or a failing channel is recovered by revoking the invited membership (CMD006) and inviting again. The replay of the same key answers the journaled 201 and delivers nothing.
- **D-TEAM-2 (accept without a tenant).** The invitee has no membership and the route names no agency. CMD004 first reads, in a short IDENTITY unit of work, the agency of the caller's own invitation (policy `membership_invitations_invitee_read`). The whole pipeline then runs in that agency's TENANT context (`runCommandIn`, scope AGENCY_HEADER, envelope agencyId from the row). An invitation the caller cannot see runs the IDENTITY pipeline and answers NOT_FOUND, identical to an unknown id or another person's invitation. The agency is never taken from the request.
- **D-TEAM-3 (lifetime).** An invitation lasts 7 days (`INVITATION_TTL_MS`). R2 says "time-limited" and fixes no number; this is the platform's single choice. R2 states no numeric member limit, so none is enforced (recorded GAP: owner may set a limit later).
- **D-TEAM-4 (CMD005).** Only an OWNER changes a role; fresh step-up (re-judged at COMMIT); `role` must be in the closed role set; INVITED and non-live targets and no-op changes are refused; the last owner cannot be demoted.
- **D-TEAM-5 (CMD006).** OWNER or ADMIN (an ADMIN never acts on an OWNER). An INVITED target is revoked together with its open invitation (`invitations.revoke` through `findByMembership`), so the token stops working. Mutual revocation of two members can deadlock in the database; the deadlock (40P01) is a retryable CAPACITY_UNAVAILABLE with no change, and is exercised in the CMD006 RACE test.
- **D-TEAM-6 (CMD007).** The successor must be an ACTIVE member of the same agency. Identity facts of the successor cannot be read under RLS (identities are readable only by their owner), so they are derived from the ACTIVE membership (acceptance = its `acceptedAt`). Residual GAP: a successor whose identity was DISABLED after acceptance is not seen by this command (it is by authentication on its first call). The two membership rows are locked in membershipId order, then the agency.

Lock order everywhere: identity, membership (shared transition lock by the authorizer), agency, client, capability. Expiry is judged at the database clock after the last lock wait (`effectNowOf`).

## GAPs of this design

- No R2 numeric member limit and no TTL value: D-TEAM-3.
- DISABLED successor identity not visible to CMD007: D-TEAM-6.
- Invitation e-mail delivery is outside B16 (the token is handed to the inviter once).
